# Transfer an instrument to another member

Keep the same instrument passport while deciding which documents to share with the next owner.

## Send a proposal

1. Complete or cancel any pending luthier work before starting a transfer.
2. Open your instrument and choose **Transfer my instrument**.
3. Enter the recipient’s **exact username**. They must already have an active account.
4. Select only the documents you want to pass on. Nothing is selected by default. Restore an archived file first if you want to select it.
5. Read the sharing explanation, confirm and send the proposal.

There can be only one pending proposal per instrument. Open **My space → Instrument transfers** to follow it. The recipient receives an in-app notification.

## Receive, accept or decline

Before acceptance, the recipient sees basic instrument identifiers and the number of selected files, without download access to them. The recipient can accept or decline; the sender can cancel. Acceptance moves the existing instrument into the recipient’s collection and opens a new ownership period.

## What moves with the passport?

- The same instrument identity, serial number, recordings, concerts and professional report revisions.
- Download access to the files explicitly selected in this proposal.
- Report attachments whose author chose to share them with current report readers.

Personal notes, private history, previous-owner notes and the former owner’s photos stay in the former owner’s private archive. Unselected invoices and private report attachments stay private. The original luthier request is not opened to the new owner.

The former owner keeps access to their uploaded documents and private archive. A recipient keeps download access to documents granted by an accepted transfer, including after a later resale. Every resale needs a new explicit document selection. Files added after a proposal are not silently included in it.

This workflow records an in-app handover. It does not collect payment or manage a sale contract. Read [document management](documents.md) and the [FAQ](faq.md) before sharing sensitive files.
